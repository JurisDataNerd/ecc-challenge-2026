# Interface direction

The memorable element is the existing pixel landscape: use a generous cropped village panorama, with quiet navigation and direct explanations alongside it. Preserve original source assets.

Palette: sky #dcebf0, paper #f5f8f6, ink #163943, forest #446c4e, trail gold #f4c566, muted ink #53696f. Geist handles navigation, headings, and body text; Pixelify Sans is restricted to the brand and short stage labels.

Desktop layout: compact brand/navigation above a split hero with left-aligned copy and a tall landscape on the right; a real three-stage sequence below. Mobile stacks copy before the landscape and preserves both entry actions.

Review against brief: avoid making the hero another gold-framed dashboard. Its illustration communicates the actual world, while the interface explains login, demo access, and the stage journey. No automatic decorative motion, repeated eyebrows, or ornamental counters.

## Interaction review

| Before | After | Why |
| --- | --- | --- |
| Separate controls and combat contact tasks | Shared movement, explicit E/touch board interaction | Predictable controls in every stage |
| Ornamental dark task frames and pixel body text | Paper dialogs with Geist body text and focused actions | Readable instructions and forms |
| No stage explanation before play | Objective, board location, and controls shown on first entry | Give players a clear first action |
| Custom overlays without focus trapping | Native modal dialogs, Escape, and focus return | Keyboard navigation stays in the active task |
| Unsaved edits disappear when closing a mission | Automatic local draft saving with storage errors surfaced | Preserve work during normal navigation |
| HUD crowded by duplicate headers | Compact stage bar and one objective, touch actions at the edges | Leave the player and map visible |
| Hover movement and delayed transitions on frequent actions | Instant keyboard dialog changes, restrained pointer press feedback | Keep repeated actions responsive |

No entrance animation is applied to keyboard-driven game/task dialogs. Reduced motion removes UI movement. Mobile landscape introduction uses two columns so both objective and controls are visible before play.
